## v0.4.4 - orchestrator-safe-cognition

Date: 2025-12-31

Summary
-------
This milestone records Phase 4 Step 4: the Orchestrator's adapter registry and config-driven LLM wiring were implemented without enabling live execution.

Key points
- Adapter registry: Adapters (deterministic and LLM-backed) are instantiated at startup from the validated `backend/orchestrator/orchestrator.json` configuration. Missing archetype entries cause startup failure (fail-fast).
- LLM client injection: `LLMClient` is dependency-injected into adapters; no global LLM instances.
- Technician adapter: Strict JSON parsing of adapter outputs; parsing failures are fail-closed and routed to Sentinel.
- Runner: Single canonical execution chokepoint implemented. Only `DryRun` behavior is permitted in this milestone; `Live` execution remains disabled.

- Ran `cargo test -p aura-backend --features "persistence search tls"`: green.

Notes
- This tag represents the safety checkpoint: LLMs are connected, but side-effecting execution is structurally impossible.
